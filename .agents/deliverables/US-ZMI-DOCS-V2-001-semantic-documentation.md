# US-ZMI-DOCS-V2-001 — Semantic, evidence-grounded documentation

## Status
FROZEN_FOR_IMPLEMENTATION

## User story
As a user who records tutorials, KT sessions, meetings and process walkthroughs,
I want Zo Media Intelligence to turn the recording into concise structured documentation and reusable grounded knowledge,
so that I can understand and reuse the content without reading a frame-by-frame transcript dump or replaying the whole video.

## Problem
The current system creates an excellent chronological evidence trail but a poor human manual because every retained frame becomes a documentation step.

## Acceptance criteria

### AC-01 Evidence preserved
Existing frame/timestamp/transcript/OCR evidence remains inspectable and traceable.

### AC-02 Semantic manual
MANUAL.md/PDF are generated from KnowledgeDocument V2, not directly from every raw frame step.

### AC-03 Explicit modes
DocumentationMode resolves using the authority order in SPEC.

### AC-04 KT quality
A synthetic 60+ minute KT-like fixture with many evidence items can produce a concise KT document with semantic sections rather than one section per evidence frame.

### AC-05 Evidence references
Every factual synthesized claim and every procedure step references valid captured evidence.

### AC-06 No hallucinated authority
Generated claims remain SYNTHESIZED_UNREVIEWED unless a human review action changes them.

### AC-07 Low confidence isolation
No-evidence/low-confidence placeholders go to review-queue.json and do not become main-manual factual prose.

### AC-08 Screenshot dedup
Manual screenshots are representative and bounded; near-identical screenshots are not repeatedly embedded.

### AC-09 RAG quality
chunks.jsonl contains semantic knowledge units, not one raw conversational chunk per frame.

### AC-10 Optional procedures
KT/meeting/reference sources may produce zero procedures.
Tutorial/process sources may produce procedure candidates only when evidence supports ordered actions.

### AC-11 KAV safety preserved
No documentation text becomes executable authority directly.

### AC-12 Project scope preserved
Knowledge package retains existing PROJECT/GLOBAL semantics and project isolation.

### AC-13 Privacy preserved
Remote LLM remains blocked for confidential projects.
No raw full transcript/VTT/media is published.

### AC-14 Existing media regeneration
An already processed recording can produce V2 evidence/manual/package without retranscription, frame extraction or OCR.

### AC-15 Last-good protection
Malformed/ungrounded synthesis cannot replace a previously valid semantic manual/package.

### AC-16 Bounded LLM use
No per-frame synthesis calls.
Calls are bounded by the block limits and one schema-repair retry maximum.

### AC-17 Provider unavailable
If synthesis provider is unavailable or privacy-blocked, evidence output succeeds with typed status and no fake semantic manual is published as complete.

### AC-18 PDF
MANUAL.pdf renders semantic document sections and representative screenshots.
The giant evidence PDF is not generated by default.

### AC-19 Compatibility
Current dashboard/API consumers expecting manual metadata/steps do not crash.
Compatibility steps.json remains available until a later cleanup US.

### AC-20 Knowledge package
Knowledge Package v2 uses synthesized title/summary/sections and only real procedure candidates.

### AC-21 No client fixtures
All committed tests use synthetic data; no P&G/client names/screenshots/transcripts are committed.

### AC-22 Human review readiness
KnowledgeDocument is persisted as editable JSON so future/current review surfaces can alter semantic sections without retranscribing.

### AC-23 Idempotency
Unchanged evidence + same synthesis settings/model + same normalized synthesis output produces stable content identity; changed semantic document produces a new knowledge version through existing version semantics.

### AC-24 Deterministic evidence
Evidence timeline creation and screenshot dedup are deterministic.

### AC-25 Existing evidence quality signal
Current evidence confidence remains visible separately from synthesis review status.

## Definition of Done for coding phase
Coding phase stops after:
- implementation complete;
- compile/typecheck;
- Ruff;
- targeted/unit tests;
- deterministic synthetic regeneration tests;
- commit + push.

It does NOT run heavy E2E/Docker/full security/Jenkins/Sonar before ChatGPT /review.
